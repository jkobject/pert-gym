- Never write to Lamin `main` from agent work. Public/main data is a read-only comparison surface.

- Treat large raw downloads as temporary cache. Durable data belongs in LaminDB or `gs://scperturb/pert-gym/staging`, not in Git.
- Clean repo-local Lamin/GCS caches after verification.
- Docs-only tasks must not alter code or data.

## Triplet contract

Canonical expression datasets use same-prefix triplets:

```text
<dataset_prefix>/obs.parquet   # cell/sample metadata
<dataset_prefix>/X.h5ad        # expression/loadable matrix; empty obs/var
<dataset_prefix>/var.parquet   # feature metadata
```

Links are `obs -> X -> var` through Lamin feature links:

```python
obs_artifact = ln.Artifact.get(key=f"{prefix}/obs.parquet")
x_artifact = obs_artifact.features.get_values()["X"]
var_artifact = x_artifact.features.get_values()["var"]
adata = x_artifact.load()
adata.obs = obs_artifact.load()
adata.var = var_artifact.load()
```

Rules:

- Every canonical triplet must have same-prefix `var.parquet`. If an old LINCS/Tahoe artifact links to shared var, duplicate or alias the verified identical var into the same-prefix key after feature-identity checks.
- RNA/expression belongs in canonical `X.h5ad`.
- Additional matrix modalities use `<prefix>/X_<name>.h5ad` linked to `<prefix>/var_<name>.parquet`.
- Embedding/obsm-style payloads use `<prefix>/obsm_<name>.parquet` or h5ad/zarr when sparse/large.
- Avoid vague untyped auxiliary blobs.
- Chunks are shards of a logical dataset, not independent biological datasets.

## Large files and GCS staging

Stage large raw downloads before they endanger local disk:

```bash
python3 tools/stage_to_gcs.py <paths...> \
  --bucket scperturb \
  --prefix pert-gym/staging \
  --delete-local
```

This verifies the uploaded object before deleting the local copy. Keep `data/main/`, `data/gcs_cache/`, raw `.h5ad`, `.tar`, `.rds`, zips, and extracted matrices out of Git.

**Caching and Egress-Avoidance Rules (added 2026-06-26):**

To reduce GCP egress costs from the Mac Mini mount:

1. **Never read GCS-FUSE repeatedly.** For repeated access or walks:
   - First materialize using `tools/gcs_cache.py gs://bucket/path`:
     ```bash
     ./tools/gcs_cache.py gs://scperturb/pert-gym/staging/data/main/prism_collection/GSE225775.h5ad
     ```
   - Then operate only on the verified local cache copy.
2. **Avoid wide scans (`find`, `ls -R`) on `/Users/jkobject/mnt/gcs/scperturb`.**
   - GCS-FUSE charges for listing ops too — use `gsutil ls` with wildcards as needed.
3. **For batch matrix reads:** prefer `gs://` URIs direct to high-memory jobs with local disk, not repeated small reads from FUSE.
4. **Keep job-local read budgets:** if a job needs to touch >100 files from GCS in a session, warn and phase it to a cache-first model.

Mac-native GCS checks/cache:

```bash
# Verify auth / object visibility.
gcloud storage ls gs://scperturb/pert-gym/staging/data/main/prism_collection/GSE225775.h5ad
gsutil ls -l gs://scperturb/pert-gym/staging/data/main/prism_collection/GSE225775.h5ad

# Materialize a staged object to a normal local path for backed readers.
./tools/gcs_cache.py gs://scperturb/pert-gym/staging/data/main/prism_collection/GSE225775.h5ad

# PRISM chunker accepts gs:// directly and caches under data/gcs_cache/.
uv run python tools/ingest_prism_large_h5ad_chunks.py \
  gs://scperturb/pert-gym/staging/data/main/prism_collection/GSE225775.h5ad \
  --dataset GSE225775 --chunk-size 1000 --max-chunks 1 --dry-run
```

`tools/gcs_cache.py` verifies remote and local byte counts and copies through a `.partial` file before exposing the cached payload.

## Git / review workflow

Canonical repo strategy as of 2026-06-22: `pert-gym` is a standalone GitHub repo at `https://github.com/jkobject/pert-gym.git`, not a subdirectory of the broader OpenClaw workspace repo. The active shared checkout is:

```text
/Users/jkobject/.openclaw/workspace/work/pert-gym
```

The shared checkout is allowed for read-only inspection, data/cache materialization, and emergency ops, but implementation/model-code cards should not pile edits directly into it. For reviewable Kanban work:

1. Start from the standalone repo metadata (`git rev-parse --show-toplevel` must resolve to the pert-gym checkout, not `/Users/jkobject/.openclaw/workspace`).
2. Use a task branch named `<type>/<task-id>-short-topic`.
3. Prefer an isolated worktree under:

   ```text
   /Users/jkobject/.openclaw/worktrees/pert-gym/<task-id>
   ```

   Example:

   ```bash
   cd /Users/jkobject/.openclaw/workspace/work/pert-gym
   git fetch origin main
   git worktree add -b fix/t_12345678-loader-contract \
     /Users/jkobject/.openclaw/worktrees/pert-gym/t_12345678 origin/main
   ```

4. Commit only reviewable code/docs/tests/artifact manifests. Exclude raw data, local caches, virtualenvs, `.omx/`, Lamin caches, generated benchmark blobs, and model-ready `.h5ad` payloads unless a task explicitly asks for a small versioned fixture.
5. Open a PR for implementation/model-code changes before marking code work done. If a worker cannot safely create the PR, it must leave a review-required Kanban block with branch/path, changed files, tests, and remaining risk.

If Git metadata is broken again, do not keep working in parent-repo fallback mode. Stop, restore the standalone repo metadata from `origin/main` without overwriting the working tree, and record the forensic backup path.
